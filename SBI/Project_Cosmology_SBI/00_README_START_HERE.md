## 0. What this project actually is (one paragraph)

You will build an **amortized neural posterior estimator (NPE)** with **BayesFlow** that, given a noisy measurement of the linear matter power spectrum `P(k)` at redshift `z = 0`, infers the joint posterior over four ΛCDM cosmological parameters **θ = {H₀, Ωₘ, nₛ, Aₛ}**. The "data" is generated by a forward **simulator**: sample θ from a prior → run **CAMB** to get the clean `P(k)` → add **cosmic-variance noise** → that noisy spectrum is one observation. You train networks on many such (θ, P(k)) pairs so that, afterwards, inference for *any* new spectrum is a fast forward pass. Then you validate calibration with **Simulation-Based Calibration (SBC)** and demonstrate inference on a held-out / Planck-fiducial "observation."

> 💡 **বাংলায়:** সহজ কথায় — তুমি একটা neural network শেখাবে: "এই রকম P(k) curve দেখলে, এর পেছনের cosmological parameter গুলো কী কী হতে পারে (পুরো posterior সহ)।" CAMB হলো সেই simulator যা parameter → P(k) বানায়; তুমি উল্টোটা (P(k) → parameter) শেখাচ্ছ।

## 2. What "100%" looks like (the grading reality)

Grade = **50% presentation + 50% report**, plus the **post-presentation Q&A** (can raise or lower your grade, and can cover *any* of the 12 course topics — not just cosmology). Pass the presentation or you fail the whole course. So three fronts must all be strong:

### A. The report must hit **every** rubric item explicitly
The official rubric (from `sbi_project_info_2026.pdf`) demands these — we map each to a deliverable in file `04`:
- Introduction (motivation, problem, modeling idea, illustrative figure)
- Data: source, how generated
- **Statistical model (simulator) with explicit *proper priors*** ← we give exact priors
- Approximator: network architectures, explicit details (layers, activations, regularization)
- Training: budget (epochs, batches, batch size), regime (offline/online), optimizer, LR schedule
- **Diagnostics: convergence + Simulation-Based Calibration + posterior contraction** ← the make-or-break section
- Inference: fit to real data, results, posterior predictive checks
- Limitations & improvements, Conclusion, Reflection

### B. The science must show real understanding (not just "ran the library")
Two things that separate a good grade from a perfect grade here:
1. **Discuss the H₀ degeneracy.** When `k` is in `h/Mpc` and `P(k)` in `(Mpc/h)³`, the spectrum's *shape* depends mostly on the **physical** combinations `Ωₘh²` and `Ω_b h²`, so H₀ alone is only weakly constrained and is **degenerate with Ωₘ**. Anticipating and explaining this in the report/viva = expert-level marks.
2. **Be honest about idealizations** (linear-only spectrum, Gaussian diagonal noise, no galaxy bias / redshift-space distortions). Graders reward students who know the limits of their model.

### C. Calibration over point accuracy
This is a *Bayesian* course taught by a calibration-focused group (Bürkner/Radev). **A well-calibrated, possibly wide/multimodal posterior is the correct scientific result — not a failure.** SBC that passes + honest contraction beats a suspiciously tight posterior. Lead with calibration.

> 💡 **বাংলায়:** teacher রা "কত নিখুঁত point estimate" দেখে না — দেখে "posterior টা সৎ আর calibrated কিনা।" তাই SBC pass করানো, contraction দেখানো, আর H₀-degeneracy ব্যাখ্যা করা = ১০০%-এর আসল চাবি।

## 6. Tech stack (all free)

- **Python** on **Google Colab** or **Kaggle** (free GPU) — project info itself suggests this.
- **CAMB** (`pip install camb`) — generates the linear P(k). Runs on CPU; one linear call is fast (~tens of ms), so 10⁴–10⁵ sims are feasible; precompute once and cache to disk (`.npz`).
- **BayesFlow ≥ 2.0** (`pip install bayesflow`) — the NPE engine. Multi-backend (Keras 3); we'll use the JAX or PyTorch backend on GPU for training.
- **NumPy / Matplotlib / (optional) getdist** — arrays, plots, corner plots.

> Detailed setup commands are in `02_Implementation_Guide.md` §1.
